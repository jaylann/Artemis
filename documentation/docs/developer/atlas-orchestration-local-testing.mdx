# Testing Atlas Competency Orchestration Locally

The autonomous Atlas flow uses real configured chat deployments. It does not provide a fake or scripted runtime.

## Configuration

Configure the existing Spring AI OpenAI client to use Logos, then set the model identifiers under `artemis.atlas.orchestrator`:

```yaml
artemis:
    atlas:
        orchestrator:
            model: gpt-5.6-luna
            reasoning-effort: xhigh
            worker-model: gpt-5.6-luna
            worker-reasoning-effort: high
```

The thesis benchmark uses the standard Spring AI tool loop through local Logos. Its configuration is in `docker/atlas-logos-benchmark`; Artemis receives only the Logos API key. There is no separate Responses transport.

Start the server with scheduling enabled and start the client normally. In Administration, enable the `AtlasAgent` feature. Edit an existing course as an administrator, enable automatic competency orchestration, and temporarily set a short debounce override for local testing.

## Manual exercise and lecture runs

1. Create at least one course competency and one unlinked programming or quiz exercise.
2. Open the exercise management detail page and run **Suggest competencies**.
3. Verify the result dialog contains the main agent's final verification message and every applied action.
4. Repeat from a text, online, or described attachment/video lecture unit in lecture-unit management.
5. Confirm blank file/video-only units and exercise-backed lecture units do not start a lecture-unit run.

## Automatic batch

1. Save several competency-relevant exercise and lecture-unit edits within one debounce window.
2. Confirm one course-scoped run processes the combined batch and produces one WebSocket completion toast.
3. Start a manual run while the course is already running and confirm the second request returns `409 IN_PROGRESS`.
4. Disable auto-orchestration for the course and confirm buffered changes are flushed.
5. Reduce the daily cap, exhaust it, and confirm subsequent changes remain buffered until the next day.

## Data checks

- New AI-created competencies and links have `generated_by_ai = true`.
- Reweighting an instructor-created link does not transfer provenance.
- AtlasML receives competency create/edit/delete notifications and refreshed exercise-to-competency mappings when AtlasML is enabled.
- Deletion is rejected while a competency still has learning-object links or competency relations.
- A failed run with applied actions returns `PARTIAL`; successful mutations are not rolled back or automatically replayed.
